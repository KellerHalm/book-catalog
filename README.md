# Book Catalog

Fullstack-приложение для работы с каталогом книг: просмотр каталога, подробная информация о книге, личный список с изменением статуса чтения.

Индивидуальное ТЗ №3 — Каталог книг.

## Стек

| Слой | Технология |
|---|---|
| Backend | Go 1.27, Gin |
| ORM | GORM |
| БД | SQLite (драйвер `github.com/glebarez/sqlite`, чистый Go, без CGO) |
| Авторизация | JWT (HS256) + bcrypt |
| Frontend | HTML / CSS / JavaScript (ES-модули, без сборки) |

## Структура проекта

```
book-catalog/
├── cmd/
│   └── server/
│       └── main.go              точка входа, graceful shutdown
├── internal/
│   ├── apperror/                типизированные ошибки с HTTP-кодами
│   ├── config/                  конфигурация из .env и переменных окружения
│   ├── database/                подключение к SQLite и миграции (AutoMigrate)
│   ├── handler/                 HTTP-хендлеры ( Gin )
│   ├── middleware/              JWT-аутентификация, обработка ошибок, лимит тела запроса
│   ├── models/                  модели GORM и статусы чтения
│   ├── repository/              работа с БД (запросы, фильтры, пагинация)
│   ├── router/                  объявление маршрутов, сборка зависимостей
│   ├── service/                 бизнес-логика и валидация
│   └── utils/                   генерация и разбор JWT
├── web/
│   └── static/                  фронтенд: index.html, css, js
├── .env.example                 пример переменных окружения
└── .gitignore
```

Слои разделены по принципу: `handler` → `service` → `repository` → БД.
HTTP-слой не обращается к БД напрямую, сервисы не знают про Gin.

## Запуск

```bash
go mod download
cp .env.example .env
go run ./cmd/server
```

Сервер поднимется на `http://localhost:8080`.
База данных создаётся автоматически в `./data/books.db`, таблицы создаются миграциями.
**Каталог стартует пустым** — книги заносятся через API или интерфейс.

Бэкенд и фронтенд отдаёт один и тот же процесс.

## Переменные окружения

Всего четыре — остальное зафиксировано в коде и меняться не должно.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `8080` | порт сервера |
| `DB_PATH` | `./data/books.db` | путь к файлу SQLite |
| `JWT_SECRET` | `book-catalog-dev-secret` | секрет подписи токенов |
| `ALLOWED_ORIGINS` | localhost и 127.0.0.1 на 8080 и 5173 | дополнительные origin через запятую |

Значения по умолчанию заданы константами в `internal/config/config.go`:
каталог статики `./web/static`, каталог загрузок `./data/uploads`,
максимальный размер изображения 5 МБ, время жизни токена 24 часа.

### CORS

Origin проверяется по белому списку, а не подставляется в ответ как `*`.
По умолчанию разрешены `http://localhost:8080`, `http://127.0.0.1:8080`,
`http://localhost:5173` и `http://127.0.0.1:5173` — на случай, если фронтенд
запущен отдельно, например через Vite.

Для запроса с чужим origin сервер отвечает `200`, но без заголовка
`Access-Control-Allow-Origin`, поэтому браузер всё равно заблокирует ответ.
Предзапрос `OPTIONS` получает `204`.

Так как фронтенд по умолчанию отдаёт тот же Go-сервер, CORS на практике
не задействуется: origin совпадает, предзапросов не возникает.

## API

Все ответы в формате JSON. Ошибки возвращаются в виде `{ "error": { "message": "..." } }`.
Для защищённых маршрутов нужен заголовок `Authorization: Bearer <token>`.

### Публичные маршруты

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/health` | проверка состояния сервера и БД |
| `POST` | `/api/auth/register` | регистрация |
| `POST` | `/api/auth/login` | вход (логин — имя пользователя или e-mail) |
| `GET` | `/api/books` | каталог с фильтрами |
| `GET` | `/api/books/genres` | список жанров, представленных в каталоге |
| `GET` | `/api/books/:id` | подробная информация о книге |

### Защищённые маршруты

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/auth/me` | текущий пользователь |
| `POST` | `/api/books` | добавить книгу в каталог |
| `PUT` | `/api/books/:id` | изменить книгу |
| `DELETE` | `/api/books/:id` | удалить книгу |
| `POST` | `/api/books/:id/cover` | загрузить обложку (multipart, поле `cover`) |
| `DELETE` | `/api/books/:id/cover` | удалить обложку |
| `GET` | `/api/my/books` | личный список |
| `GET` | `/api/my/stats` | статистика по статусам |
| `POST` | `/api/my/books/:bookId` | добавить книгу в личный список |
| `PATCH` | `/api/my/books/:id` | изменить статус чтения |
| `DELETE` | `/api/my/books/:id` | убрать книгу из личного списка |

### Параметры `GET /api/books`

| Параметр | По умолчанию | Описание |
|---|---|---|
| `search` | — | поиск по названию, автору или жанру, без учёта регистра |
| `genre` | — | фильтр по жанру |
| `sort` | `id` | `title`, `author`, `year`, `rating` |
| `page` | `1` | номер страницы |
| `per_page` | `12` | элементов на странице, максимум 100 |

### Статусы чтения

| Значение | Отображение |
|---|---|
| `want_to_read` | Хочу прочитать |
| `reading` | Читаю |
| `finished` | Прочитано |

## Примеры запросов

Регистрация:

```bash
curl -X POST http://localhost:8080/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"username":"ivan","email":"ivan@example.com","password":"password123"}'
```

Вход:

```bash
curl -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"login":"ivan","password":"password123"}'
```

Добавление книги (нужен токен):

```bash
curl -X POST http://localhost:8080/api/books \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{
    "title": "Мастер и Маргарита",
    "author": "Михаил Булгаков",
    "genre": "Классика",
    "year": 1967,
    "pages": 480,
    "rating": 4.8,
    "description": "Роман о дьяволе, который пришёл в Москву."
  }'
```

Загрузка обложки (необязательна):

```bash
curl -X POST http://localhost:8080/api/books/1/cover \
  -H "Authorization: Bearer <token>" \
  -F "cover=@dune.jpg"
```

Поиск по каталогу:

```bash
curl "http://localhost:8080/api/books?search=мастер&genre=Классика&sort=rating&page=1&per_page=12"
```

Добавление в личный список и смена статуса:

```bash
curl -X POST http://localhost:8080/api/my/books/1 \
  -H "Authorization: Bearer <token>"

curl -X PATCH http://localhost:8080/api/my/books/1 \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{"status":"finished"}'
```

## Формат ответов

Список книг:

```json
{
  "items": [ { "id": 1, "title": "...", "author": "...", "genre": "..." } ],
  "meta": { "page": 1, "per_page": 12, "total": 20, "total_pages": 2 }
}
```

Личный список дополнительно содержит статистику:

```json
{
  "items": [
    {
      "id": 1,
      "book_id": 1,
      "status": "reading",
      "added_at": "2026-09-29T10:09:30Z",
      "book": { "id": 1, "title": "...", "author": "..." }
    }
  ],
  "meta": { "page": 1, "per_page": 12, "total": 1, "total_pages": 1 },
  "stats": { "want_to_read": 0, "reading": 1, "finished": 0, "total": 1 }
}
```

## Коды ошибок

| Код | Значение |
|---|---|
| `400` | некорректные данные запроса |
| `401` | не передан токен, токен недействителен или истёк |
| `404` | ресурс не найден |
| `409` | конфликт: логин занят, книга уже в списке |
| `500` | внутренняя ошибка сервера |

## Реализованные решения

- **Регистронезависимый поиск для кириллицы.** `LIKE` в SQLite не учитывает регистр вне ASCII, поэтому в модели книги есть служебные поля `search_index` и `genre_index`, которые заполняются в хуке `BeforeSave` через `strings.ToLower`. Поисковый запрос приводится к нижнему регистру в Go, где `ToLower` работает с Unicode.
- **Пароли** хранятся в виде bcrypt-хешей, пароль никогда не возвращается в ответах API.
- **Токен** содержит `user_id`, `username`, `iat`, `exp`; при истёкшем токене защищённые маршруты отвечают `401`, а не `403`.
- **Уникальность** книги в личном списке обеспечена составным индексом `(user_id, book_id)`, повторное добавление возвращает `409`.
- **Пагинация** ограничена 100 элементами на страницу, некорректные параметры заменяются значениями по умолчанию.
- **Обложка необязательна.** Поле `cover_url` остаётся пустой строкой, и фронтенд рисует заглушку. При загрузке тип файла определяется по содержимому через `http.DetectContentType`, а не по расширению, поэтому переименованный `.exe` не пройдёт. Имя файла генерируется случайно, чтобы исключить перезапись и выход за пределы каталога. При повторной загрузке старый файл удаляется с диска.
